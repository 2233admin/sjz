# 前端重做：调研结论与设计决策

## 一、现有前端到底哪里差

先纠正一个误判：**配色不是问题**。现有 CSS 用的是 GitHub Primer 的色板
（`#0d1117` / `#161b22` / `#2f81f7`），有 CSS 变量、有 hover/focus 状态、
有 pill / meter / seg 组件，远超"随手拼的"水平。

真正的问题在**布局和信息架构**。

### 1.1 预览区比例失衡（最大问题）

```css
grid-template-columns: 1fr 380px;   /* 预览 800px + 面板 380px */
```

1180px 窗口下，预览占 800px。但预览**只在「框选」页有用**——用户要在上面拖框。
其余三页（任务队列、砖皮、运行）里，这 800px 只有：

- 一块没人看的屏幕实时画面
- 已经在预览上叠着的区域框

结果是：**四个页面共用一个为其中一页服务的布局**。

### 1.2 关键信息离视线太远

抢购进行中，用户需要同时看到：

| 信息 | 现在的位置 | 要滚动吗 |
|---|---|---|
| 状态机（扫描中/开抢中） | 运行页第 4 个 section | 要 |
| 点击次数 / 匹配分数 | 同上 | 要 |
| 日志 | 运行页第 5 个 section | 要 |
| 停止按钮 | 运行页第 1 个 section | 不用（但在最上面） |

**状态和日志是抢购时唯一要看的东西，却埋在最深的地方。** 而顶部状态条只给了
四个 pill（时钟/网络/屏幕/状态），信息密度太薄。

### 1.3 任务队列与执行分离

加了任务要去「任务队列」页确认，开抢要去「运行」页点。抢购时来回切标签，
每次都丢失滚动位置。

### 1.4 队列行没有"行尾操作"

现在每条任务的操作按钮是块状堆叠还是行内？见 `renderTasks`。Cronicle 的做法是
**一行放完所有字段 + 行尾集中操作**，扫视成本低得多。

## 二、调研来源与取舍

### 2.1 关键纠正：不要照抄 SikuliX 主界面

任务原本假设「SikuliX 是屏幕图像识别工具，所以照它的 IDE 布局抄」。调研证实
这是**错的**：

> SikuliX **不是**左侧常驻游戏预览、右侧区域列表。实际截图里：顶部工具按钮、
> 左侧命令面板（Find / Mouse Actions / Keyboard Actions）、中央带标签页的脚本
> 编辑器、下方 Message 输出区。

它是**给程序员写脚本用的 IDE**，本项目是**给玩家用的操作台**。抄它的布局会把
目标用户搞晕。

**但要抄它的 Pattern Settings 三页分工**（2.0.5 源码确认）：

| 标签 | 解决什么 | 对应本项目 |
|---|---|---|
| Naming | 给模板起名 | 区域名称（购买/确认/商品名/价格） |
| Matching Preview | 看匹配到哪、阈值多少 | 「当前相关度」+ 预览叠加框 |
| Target Offset | 调点击点相对匹配中心的偏移 | 点击目标十字 + X/Y 微调 |

这个分工很对：**模板、阈值、点击点是三件事**，现在代码把它们混在一排。

### 2.2 各屏幕的来源映射（采纳）

| 本项目屏幕 | 主参考 | 抄什么 | 不抄 |
|---|---|---|---|
| **主工作台** | OBS | 大预览 + 区域列表联动 | 场景切换、音频台 |
| **框选区域** | ShareX + SikuliX | 放大镜、十字、保存后出缩略图 | 上传、涂鸦 |
| **模板调试** | SikuliX 2.0.5 | 匹配预览、阈值数值、目标偏移 | IDE、命令面板 |
| **点击配置** | Pulover's Macro Creator | 重复次数/延迟分组 | 全部鼠标动作 |
| **启动/停止** | G HUB | 明确触发方式与停止条件、显示当前模式 | 外设映射、灯效 |
| **任务队列** | Cronicle | 行内启用、名称、时间、倒计时、行尾操作 | Plugin、服务器、分类整行色 |
| **运行记录** | Windows 任务计划程序 | 状态/下次/上次 分列 | MMC 树 |
| **日志** | Docker Desktop + Woodpecker | 工具条（搜索/时间戳/复制/清屏）+ 等宽三列 + 暂停跟随 | 容器/CI 管理 |
| **校时/测速** | 无贴近参考 | 保留现状 | 不硬套别的产品 |
| **砖皮知识库** | 无专门参考 | 保留现状 | — |

### 2.3 日志区可直接取用的数值（Woodpecker 源码）

```css
--log-head-bg: #242526;    /* 深色日志工具条背景 */
--log-body-bg: #121314;    /* 深色日志正文背景 */
--ansi-red:    #FF7070;
--ansi-green:  #B0F986;
--ansi-yellow: #C6C502;
--ansi-blue:   #8DB7E0;
--ansi-cyan:   #6BF7FF;
--ansi-white:  #9CA3AF;
```

分栏用 grid，不要用空格补齐：

```css
grid-template-columns: min-content minmax(0,1fr) min-content;  /* 行号 | 正文 | 时间 */
```

自动滚动的判定：**距底部 < 5px 才跟随**；用户上翻时不强制拉回。

### 2.4 一个必须避开的坑

Cronicle 的 Schedule 表格有整行背景色（red `#FFE0E0` / green `#D8FFD8` 等），
但官方文档明确那是**分类标签色，不是成功/失败状态**。不要把它当状态色抄。

同理 SikuliX 的匹配矩形用 HSB 连续色带（alpha 20→150），**高分也可能是红色**，
不是"绿=成功红=失败"。

## 三、我的设计决策

### 3.1 布局：三栏，但预览可折叠

调研推荐的「大预览 + 右侧区域列表」对**框选**是对的，但对其余三页是浪费。
所以：

```
┌─────────────────────────────────────────────────────────┐
│ 顶栏：标题 · 模式 · 时钟 · 网络 · 状态 · [停止]          │  ← 52px 固定
├──────────────┬──────────────────────────┬───────────────┤
│ 左栏 240px   │  中栏 自适应             │ 右栏 300px    │
│              │                          │               │
│ 导航         │  主内容区（随导航切换）  │  实时状态     │
│ · 框选       │                          │  · 状态机     │
│ · 任务队列   │  - 框选页：预览+拖拽     │  · 点击次数   │
│ · 交易行     │  - 队列页：任务表        │  · 匹配分数   │
│ · 运行       │  - 运行页：控制+校时     │  · 相关度条   │
│ · 砖皮       │                          │  ─────────    │
│              │                          │  日志         │
│              │                          │  （常驻）     │
└──────────────┴──────────────────────────┴───────────────┘
```

**关键改变**：

1. **右侧栏常驻**，放状态和日志 —— 抢购时不用切页就能看到全部关键信息
2. **左侧竖排导航替代横排标签** —— 5 项竖排比 4 项横排更容易扫视，且给图标留位置
3. **预览只在框选页出现**，其余页把空间让给内容

### 3.2 为什么不选"保持现有两栏、只调比例"

因为问题不是比例，是**信息架构**：状态和日志必须在任何页面都可见。两栏做不到
这点，除非把状态塞进顶栏——但那样顶栏会过载。

### 3.3 技术约束：保持 id 契约

现有 JS 引用 **65 个元素 id**（另有一个 `toast` 动态创建）。重做 HTML 时
**必须全部保留**，否则 JS 全挂。已提取完整清单，重做后逐一核对。

关键的几何依赖（框选逻辑）：
- `#wrap` > `#stream` + `#overlay` + `#rubber` 的嵌套关系不能变
- `syncOverlay()` 靠 `stream.getBoundingClientRect()` 和 `wrap` 的相对位置
- `.box` 元素在 `#wrap` 内绝对定位
